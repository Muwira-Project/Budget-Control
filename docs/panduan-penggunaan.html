Dokumen untuk pengguna aplikasi (admin & staff)

1. Tentang Aplikasi

myfinance adalah aplikasi web untuk mengelola keuangan perusahaan berbasis budget (alokasi dana) per project. Aplikasi ini mencatat budget (rencana dana), actual (realisasi/penggunaan dana), dan variance (selisih) di setiap project, serta dilengkapi modul keuangan: Payment Request, Cashflow, Receivable (piutang), Payable (hutang), dan Monitoring periode.

Aplikasi ini dipakai oleh dua jenis pengguna:

  • Admin - mengelola seluruh data: project, budget, actual, monitoring, keuangan, master data, user, dan backup.
  • Staff - melihat dashboard dan monitoring, serta membuat draft Budget Allocation dan Payment Request miliknya.

2. Cara Masuk (Login)

  1. Buka alamat aplikasi (contoh: https://namaserver/).
  2. Masukkan email dan password yang sudah didaftarkan admin.
  3. Klik tombol Sign in / Masuk.
  4. Jika lupa kata sandi, hubungi admin untuk mengatur ulang akun.
Catatan: pendaftaran akun sendiri (register) dinonaktifkan. Akun hanya dibuat oleh admin melalui menu Master > User.

4. Rincian Fitur dan Cara Pakai per Modul

4.1 Dashboard

Halaman pertama setelah login. Menampilkan kartu ringkasan dan grafik agar kondisi keuangan terlihat sekilas.

  • Kartu: Project, Budget, Allocation, Actual, Variance, Nilai Kontrak, Pajak, Saldo Kas, Outstanding AR/AP, Profit per Project.
  • Grafik: Budget vs Actual (top 10) dan Actual per kategori.
  • Gunakan filter rentang tanggal (Dari/Sampai) untuk melihat angka sesuai periode yang diinginkan.
Variance negatif berarti penggunaan dana melebihi budget (over budget). Angka ini menjadi bahan evaluasi, bukan pemblokir input.

4.2 Project

Project adalah induk dari semua pencatatan. Cara memakai:

  1. Buka menu Project, klik Create / Tambah Project.
  2. Isi kode, nama, lokasi, jenis (barang/jasa), qty, satuan, harga satuan, pajak, tanggal mulai, dan target selesai.
  3. Simpan. Data project bisa diedit (Edit) atau dihapus (Delete).

4.3 Account (COA)

Daftar master akun yang dipakai di seluruh project (contoh: Pendapatan, Upah, Material, Sewa).

  • Filter berdasarkan jenis akun (Pendapatan/Pengeluaran) dan kategori.
  • Fitur sort untuk mengurutkan kolom.
  • Pilih periode tanggal; kolom actual muncul otomatis sesuai periode tersebut.
  • Klik detail pada sebuah akun untuk melihat transaksi yang memakainya.

4.4 Budget

Merencanakan budget per project per periode bulanan (YYYY-MM).

  1. Buka menu Budget, klik Create.
  2. Pilih project dan periode, lalu isi estimasi pendapatan dan rincian budget per akun (estimasi biaya dihitung otomatis dari rincian; target laba = pendapatan - biaya).
  3. Setiap rincian akun bisa diberi rentang tanggal mulai-selesai.
  4. Simpan. Satu project hanya boleh punya satu plan per periode.

4.5 Monitoring

Pengganti menu alokasi lama. Menampilkan perbandingan Budget vs Actual In vs Actual Out vs Variance per periode.

  • Kolom: Nomor, Periode (rentang tanggal), Week (otomatis 1/2/3), Month (otomatis), Budget (ditarik dari Budget Plan sesuai tanggal), Actual, Variance.
  • Berlaku per project dan global (tanpa filter project).
  • List periode bisa diedit atau dihapus; klik sebuah periode untuk melihat resume periode: seluruh akun + budget + actual.

4.6 Payment Request

Permintaan pembayaran yang mengikuti alur persetujuan.

  1. Buat Draft dengan memilih project, akun, pihak (vendor/supplier/mandor/investor), tanggal, jatuh tempo, nominal, dan prioritas (High/Medium/Low).
  2. Ajukan menjadi Waiting (menunggu persetujuan admin).
  3. Admin Approve atau Reject. Permintaan yang disetujui otomatis menjadi Payable (AP) dan memengaruhi Cashflow.
  4. Setelah dibayar, tandai Paid lalu Closed (atau Cancelled).
Payment Request yang disetujui otomatis menjadi hutang (Payable) - tidak perlu dicatat dua kali.

4.7 Cashflow

  • Cash In: pendapatan manual + pelunasan piutang (AR).
  • Cash Out: payment request yang dibayar + pelunasan hutang (AP).
  • Halaman menampilkan total masuk, total keluar, dan saldo; lengkap dengan filter.

4.8 Receivable & Payable

  • Account Receivable (AR): piutang ke klien. Terbentuk otomatis saat project selesai, sebesar nilai kontrak. Status: Belum Dibayar / Sebagian / Lunas.
  • Account Payable (AP): hutang ke vendor/supplier. Terbentuk otomatis dari Actual dan dari Payment Request yang disetujui.
  • Payment: riwayat pelunasan. Membayar AR menambah saldo kas (masuk); membayar AP mengurangi saldo kas (keluar).

4.9 Actual

Ledger otomatis penggunaan dana (tanpa input manual). Data Actual dibuat otomatis oleh sistem dari transaksi di modul lain:

  • Actual Out: Payment Request yang dibayar dan pelunasan hutang (AP) yang tidak berasal dari Payment Request.
  • Actual In: penerimaan dari pelunasan piutang (AR).

Halaman ini hanya menampilkan riwayat (read-only) lengkap dengan sumber transaksinya, bisa difilter per project, akun, dan rentang tanggal, serta diekspor ke Excel/PDF.

Karena Actual otomatis, tidak ada lagi tombol tambah/edit/hapus atau import di menu ini. Semua angka terkait (Monitoring, Dashboard, laporan) mengikuti transaksi di modul pembayaran.

Pengeluaran di luar project (mis. listrik kantor) dicatat di menu Non-Project Expense; pengeluaran ini ikut Actual Out global di Monitoring tetapi tidak membebani budget project mana pun.

4.10 Backup

Menu khusus admin untuk menjaga keamanan data.

  1. Buka menu Backup.
  2. Klik Buat Backup untuk membuat cadangan database (proses beberapa detik).
  3. File backup muncul di daftar; klik ikon unduh untuk menyimpan ke komputer.
  4. Untuk membersihkan backup lama sesuai aturan penyimpanan, klik Bersihkan Backup Lama.
  5. File yang tidak diperlukan bisa dihapus lewat ikon hapus.
Lakukan backup secara rutin, terutama sebelum perubahan besar atau setelah input data penting.

4.11 Audit Log

Semua perubahan data tercatat otomatis: siapa, kapan, dan apa yang diubah (create/update/delete). Cukup dibaca untuk keperluan audit.

4.12 Master Data

  • Category: klasifikasi akun (misal: Biaya Umum, Vendor/Jasa, Supplier, Investor, Material, Pajak).
  • Vendor: pihak penyedia jasa (kode, nama, telepon, alamat).
  • Supplier: pihak penyedia barang (kode, nama, telepon, alamat).
  • Mandor & Investor: master terpisah seperti Vendor/Supplier.
  • User: akun pengguna dengan foto profil, nama, departemen, tanggal masuk, lokasi, dan peran (admin/staff). Bisa diedit atau dihapus.

4.13 Fitur Pendukung

  • Notifikasi: lonceng di atas halaman untuk over budget, user baru, dan Payment Request yang menunggu persetujuan.
  • Pagination: pilih jumlah baris per halaman (25/50/dst) dan lompat ke halaman tertentu.
  • Hapus massal (checklist): pilih beberapa baris lalu hapus sekaligus, ala Accurate.
  • Import/Export per modul: import Account & Actual dari template Excel; export ke Excel/PDF.
  • Filter rentang tanggal di halaman yang membutuhkan.

5. Alur Penggunaan (End-to-End)

Berikut urutan kerja yang disarankan agar data tersusun rapi dan laporan akurat:

UrutanLangkahMenu
1Lengkapi master data: category, vendor, supplier, mandor, investor, dan user.Master
2Buat project baru (jenis, qty, harga, pajak, tanggal).Project
3Susun Budget Plan per project per periode (rincian per akun).Budget
4Alokasikan budget ke akun dan ajukan persetujuan (draft lalu approve).Allocation (di dalam Monitoring)
5Catat penggunaan dana: input Actual, atau buat Payment Request lalu dibayar.Actual / Payment Request
6Pantau Budget vs Actual vs Variance di Monitoring (per project & global).Monitoring
7Saat project selesai, piutang (AR) terbentuk otomatis; pantau pelunasan di Receivable & Payment.Receivable & Payable
8Periksa saldo kas dan profit di Dashboard; lakukan backup rutin.Dashboard / Backup

Alur singkat pencatatan transaksi

  1. Penerimaan pendapatan dicatat di Cashflow (Cash In).
  2. Pengeluaran lewat Payment Request: draft, waiting, approved, paid, closed.
  3. PR yang disetujui otomatis menjadi Payable (AP); pelunasannya mengurangi kas (Cash Out).
  4. Project selesai otomatis menjadi Receivable (AR); pembayaran klien menambah kas (Cash In).
  5. Semua angka terlihat di Dashboard dan Monitoring.

6. Tips dan Hal yang Perlu Diperhatikan

  • Selalu isi master data sebelum membuat project agar pilihan pihak dan akun tersedia.
  • Actual hanya bisa diinput ke akun yang sudah dialokasikan ke project (dan alokasi disetujui).
  • Variance negatif = over budget; segera cek penyebabnya di Monitoring.
  • Gunakan prioritas pada Payment Request (High/Medium/Low) agar urutan pembayaran jelas.
  • Ekspor data secara berkala (Excel/PDF) sebagai arsip tambahan selain backup.
  • Hapus akun atau data penting hanya jika yakin; semua perubahan tetap tercatat di Audit Log.

7. Lampiran: Rencana Pengembangan

Berikut catatan rencana dari notulensi terbaru yang belum seluruhnya tersedia di versi ini. Fitur ini sedang dibahas/dikerjakan bertahap.

  • Estimasi dan target income pada Budget dihapus (ditahan, menunggu perkembangan).
  • Pengeluaran non-project dicatat terpisah dari project dengan logika actual — selesai 2026-08-10 (menu Non-Project Expense).
  • Monitoring: filter periode project dan export summary CSV/XLS/PDF per periode — selesai 2026-08-10.
  • Actual otomatis menarik data dari modul (tanpa input manual) — selesai 2026-08-10: Actual Out dari pembayaran, Actual In dari pelunasan piutang.
  • Project selesai = piutang; piutang dibayar = actual penerimaan (ditahan, menunggu perkembangan).
